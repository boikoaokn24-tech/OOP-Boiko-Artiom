## Висновок

Під час виконання лабораторної роботи №18 було досліджено та практично застосовано створення власних класів винятків і патерн `Result<T>` для гнучкого контролю помилок у мові C# (.NET SDK).

На прикладі Варіанту 2 («Управління користувачами») було реалізовано:
* **Власний виняток `UserNotFoundException`**, успадкований від `Exception`, із додатковою властивістю `Username` та набором стандартних конструкторів для точної діагностики відсутності облікового запису під час пошуку (`GetUser`).
* **Узагальнений клас `Result<T>`** із фабричними методами `Success`, `Failure(string)` та `Failure(Exception)` для інкапсуляції результату виконання операції без генерації винятків.
* **Розділення стратегій обробки помилок у `UserService`**: метод `RegisterUser` повертає `Result<bool>`, оскільки некоректний пароль або зайнятий логін є штатними, очікуваними сценаріями валідації при введенні даних користувачем; натомість метод `GetUser` викидає `UserNotFoundException`, оскільки запит на отримання обов'язкового користувача за неіснуючим іменем свідчить про порушення очікуваного стану програми.

Поєднання власних винятків та патерну `Result<T>` дозволило уникнути витрат продуктивності на розгортання стеку при звичайних помилках валідації та зробити код більш передбачуваним і читабельним.
